## 3. 대기열 · 배정 — 동시성

지금은 각 브라우저의 `_reconcile()` 이 "내가 보기에 다음 차례" 를 스스로 판단한다. 사용자가 둘 이상이면 **같은 기기에 두 명이 배정될 수 있다.**

- 줄서기 · 배정 · 취소 · 종료를 **서버 API 로 옮기고**, 대기열 갱신은 트랜잭션(또는 행 잠금)으로 처리한다
- 배정은 서버가 정하고 클라이언트는 결과만 받는다 (`홈.dc.html` `_reconcile` · `queueType` · `leave` · `finish` 가 그 자리)
- "가장 먼저 끝나는 기기에 배정" (05 P2) 규칙도 서버로 옮긴다
- 줄 개수 제한(세탁기 1줄 · 건조기 1줄 · 05 P1), 다시 서면 맨 뒤(05 P8), **배정 상태에서는 줄 빠지기 불가**(05 P3), 제한 중 · 점검 중 차단(05 P7 · P20)도 화면이 아니라 서버가 막는다
- **관리자의 실시간 대기열(F23)은 지금 같은 브라우저 안에서만 맞는다.** 홈이 `washed_typequeue` 에 남긴 값을 관리자 화면이 읽는 구조라, 관리자가 다른 기기 · 다른 브라우저에서 열면 대기열이 비어 보인다. 대기 인원을 세는 규칙(05 P2 — 빈 기기가 있으면 0명)은 **홈과 관리자 양쪽에 같은 식으로 적혀 있으므로**, 서버로 옮길 때는 그 규칙을 **한 곳(대기열 조회 API)에만** 두고 두 화면이 같은 응답을 받게 한다

## 4. 시간 · 만료 처리

| 지금 | 바꿀 것 |
|---|---|
| 브라우저의 `Date.now()` 로 남은 시간 계산 | 서버 시각 기준. 화면은 서버가 준 종료 시각까지의 차이만 그린다 |
| 화면이 켜져 있어야 만료가 처리된다 | **서버 스케줄러**가 처리한다 — 배정 10분 만료, 수거 3분 초과, 제한 3일 종료, 매월 1일 경고 초기화 |
| `setInterval(..., 1000)` 으로 화면 전체 갱신 | 서버 푸시(SSE · WebSocket)나 짧은 폴링으로 바꾼다 |

**기산점을 서버가 정한다.** 다음 사람의 배정 10분은 앞사람이 "다했어요" 를 눌렀거나 3분이 지나 자동 종료되어 **기기가 사용가능이 된 서버 시각**부터 센다(02 「시간 흐름」 · 05 상태값). 앞사람의 3분은 다음 사람의 10분에 들어가지 않는다.

**경고는 한 번만 쌓는다.** "다했어요" 미클릭과 세탁물 미수거가 겹쳐도 통합 1회다(05 P6) — 자동 판정과 관리자 수동 부여가 같은 건에 두 번 붙지 않도록 서버에서 막는다.

**앱을 안 켠 사람도 경고를 받아야 한다.** 지금은 화면을 열지 않으면 배정 만료 경고가 기록되지 않는다.

## 5. 알림

- 지금은 화면 안 토스트와 알림함 목록뿐이다. **실제 푸시가 없다**
- 배정 · 종료 · 경고 · 공지 · 신고 결과 발송을 서버에서 처리하고, 기기 토큰(FCM · APNs)을 사용자별로 저장한다
- `설정.dc.html` 의 알림 토글(`tenMin` · `ready`)은 화면 state 라 새로 고치면 초기화된다 → 사용자 설정 테이블로. "차례 10분 전 알림" 은 **내 차례가 오기 10분 전**이고, 세탁 종료는 별도 알림이다(04 F9 · F19 · 05 P13)
- 신고 결과 알림은 **신고자에게만** 보낸다(05 P19)
- 알림 보관 30일(05 P14)은 서버 배치로 삭제한다. **「공지」 종류만 3개월**이라 배치가 종류를 보고 기간을 갈라야 한다(05 P14 의 예외 · P18). 지금은 `알림.dc.html` 의 `KEEP_DAYS(type)` 이 화면에서 거르기만 한다

## 6. QR 인증

- 현재 스캐너는 **카메라를 쓰지 않는 연출 화면**이다 (`홈.dc.html` `scanningId` · `closeScanner`)
- 카메라 권한 요청 + QR 디코딩 라이브러리 연결이 필요하다
- QR 값에는 기기 ID 와 함께 **위조 · 재사용을 막을 값**(서명 또는 한 번 쓰고 버리는 토큰)을 넣는다. 사진으로 찍어 두고 방에서 인증하는 것을 막아야 한다
- 서버는 "배정된 사람인가 · 그 기기가 맞는가 · 10분이 지나지 않았는가" 를 확인한 뒤 타이머(세탁 60분 · 건조 45분 · 05 P4)를 시작한다
- **QR 을 찍지 않고 쓰면 앱은 사용가능으로 본다** — 자동으로는 막지 못하고 신고(05 P4 순서 미준수 사유 · F11)로만 잡힌다

## 7. 파일 업로드 (신고 증거 사진)

- `설정.dc.html` 의 `<image-slot id="report-evidence">` 는 **첨부 UI 만 있고 신고 데이터에 사진이 들어가지 않는다** — `submitReport` 가 `washed_reports` 에 넣는 값에 사진 칸이 없다
- 증거 사진은 **"세탁물이 있어요" 사유에만 뜨고 필수**다(05 P15). 화면은 `showEvidenceSlot` · `canSubmit` 으로 막고 있지만 **서버에서도 같은 조건을 확인해야 한다** — 이 사유의 신고는 사진이 있어야만 접수된다
- 업로드 API · 저장소(S3 등) · 용량 제한 · 보관 기간이 필요하다. 사진에는 다른 사람의 세탁물이 찍히므로 보관 기간을 짧게 두고 신고 종결 시 삭제한다(05 P23 — 올린 시점부터 3개월 · 신고자 탈퇴 시 함께 삭제)

## 8. 화면에 박혀 있는 가짜 데이터

| 화면 | 항목 |
|---|---|
| 관리자 | 기기 목록(세탁기 8 · 건조기 4) — **홈은 이제 `listMachines()` · `queueCounts()` 를 읽는다**(`/api/machines`). 관리자 콘솔은 아직 옮기지 않았다 |
| 관리자 | 사용자 목록 `userDefs`(이름 · 학번 · 학교 · 호실 · 기본 경고 수), 신고 샘플 `reportDefsAll`, 공지 기본값, 이용 내역 샘플 `historyDefsAll` |
| 기록 | 이용 내역 `groups` 샘플, 경고 샘플 |
| 알림 | 샘플 알림 `n1` ~ `n9` |
| 관리자 대기열 | 대기 인원 · 첫 대기자 남은 시간 · 기기 대수는 **이제 홈이 남긴 실제 값을 읽는다**(`liveQueue`). 남아 있는 가짜 값은 스냅샷이 아예 없을 때만 쓰는 `mockTotal`(세탁기 8 · 건조기 4)과, 대기 줄에 붙는 이름 문자열 `'병찬 · 302호 (앱 사용자)'` 뿐이다 |

전부 API 조회로 바꾼다. 화면 구조는 그대로 두고 `renderVals()` 안의 배열만 교체하면 된다.

**05 P20 의 문서상 정의와 실제 구현이 다르다.** P20 은 "세탁실 전체를 잠그는 관리자 토글"로 적혀 있고 06-data.md 에도 그 모양(F33 · v2)으로만 남아 있는데, 관리자 콘솔(`admin-actions.ts` · `tabs.tsx`)은 이미 **기기 하나 단위**로 `'점검중'` 상태를 켜고 끄는 형태로 만들어져 있었다 — DB `CHECK` 제약이 이 값을 막고 있었을 뿐이다(0005 마이그레이션에서 풀었다). 홈 화면(F1)은 이 **기기 단위 점검중**을 고장과 같은 자리에서 읽어 보여준다. "세탁실 전체를 한 번에 잠그는" 원래 P20 의 토글은 여전히 만들지 않았다 — 팀이 두 개념 중 무엇을 정책으로 남길지 정리해야 한다.

**조회 기간은 네 곳에서 각각 잘린다.** 지금은 화면마다 컷오프를 따로 계산한다 — 관리자는 `historyCutoff`(이용 내역) · `noticeCutoff`(공지) · `reportCutoff`(신고) · `warnLogCutoff`(경고 사유)와 월 목록 3개월, 사생은 `기록.dc.html` 의 `warnCutoff`(30일)와 `알림.dc.html` 의 `KEEP_DAYS(type)`(30일 · 공지 90일)이다. 서버로 옮기면 **보관 기간은 삭제 배치 한 곳에, 조회 기간은 각 조회 API 에** 두고 화면에서는 자르지 않는다(05 「보관 기간과 조회 기간」).

**월 목록은 만들어 쓰는 값이다.** 관리자 경고 탭의 월 드롭다운은 **현재 달부터 3개월**을 그때그때 계산해 만들고(고른 달이 목록에서 사라지면 현재 달로 되돌린다), 이용 내역 · 공지의 월 드롭다운은 **실제 데이터가 있는 달**만 모아 만든다. 서버로 옮겨도 이 방식(달 목록을 저장하지 않고 조회 결과에서 뽑는다)을 그대로 둔다. **세 목록의 상한은 모두 보관 기간 3개월**이다(05 P17 · P18 · SP4) — 보관 기간을 바꾸면 세 곳을 함께 본다.

## 9. 보관 · 삭제 (05 P14 · P17 · P18 · P21 · P23 · P24 · SP4 · SP5)

- 이용 내역 · 경고 · 신고(증거 사진 포함) 3개월, 알림 30일(**「공지」 종류만 3개월** · 05 P14), 공지 3개월(05 P18) → **서버 배치 삭제** · 사생 기록 화면 30일은 삭제가 아니라 **조회**다(05 P21). 전체 대조표는 05 「보관 기간과 조회 기간」에 있다
- 공지 3개월은 지금 **관리자 화면이 목록에서 거를 뿐**이다(`liveNotices`) — `washed_notices` 에는 그대로 남아 있다. 서버에서는 **지우는 규칙과 보여주는 규칙을 층으로 나눈다**: 「공지」 행 자체는 **등록 + 3개월** 에 배치로 지우고(05 P18), 사생 알림함의 **30일**(05 P14)은 지우는 규칙이 아니라 **조회 필터**로 남긴다. 지워진 뒤에는 어느 화면에도 없으므로 관리자 쪽 조회 필터는 없애도 된다
- 「공지」는 F26 이 MVP 로 올라오면서 **저장 항목이 되었다**(06 「공지」 — 제목 · 내용 · 등록 시각 · 보관 3개월). `washed_notices` → `notice` 테이블
- 탈퇴는 **즉시 삭제가 아니라 14일 유예**다(05 P24) — 탈퇴 신청 시각을 저장하고, 매일 배치로 `탈퇴 신청 + 14일` 이 지난 계정의 개인정보 · 이용 내역 · 경고 · 신고 · 알림 · 업로드한 사진을 삭제한다. 익명화가 아니라 삭제다
- 복구 기간에는 로그인 시 홈 대신 복구 안내를 띄우고, 같은 학교 이메일의 신규 가입을 막는다

## 10. 확장할 때 걸리는 것

- **세탁실이 한 곳이라는 전제**로 되어 있다. 동 · 층이 여러 개면 기기 · 대기열 · 공지 · 점검 모드가 모두 세탁실 단위로 나뉘어야 한다
- 관리자 계정이 하나다. 동별 담당자를 나누려면 관리자에게도 소속이 필요하다(06 의 [?] 와 같은 건)
- 네트워크 오류 · 서버 점검 중의 화면이 없다. 모든 조회에 실패 상태 표시가 필요하다
- **고정 타이머(60분 · 45분)가 실제 코스와 어긋나는 경우**가 아직 열린 질문이다(04 · 05 P4). 코스 선택을 넣게 되면 기기 항목의 "종료 예정 시각" 계산과 4번 스케줄러가 함께 바뀐다

## 11. 다국어 (04 F37 · 05 P25)

- 번역은 `i18n.js`(화면 문구) · `i18n-docs.js`(약관 · 개인정보 동의서)의 **한국어 원문을 키로 쓰는 사전**이다. 화면을 만들 때 문구를 새로 쓰면 사전에도 같이 넣어야 하고, 넣지 않으면 **오류 없이 한국어 그대로 보인다** — 배포 전 네 언어로 한 번씩 돌아보는 점검이 필요하다
- 지금은 `MutationObserver` 로 DOM 의 텍스트 노드를 훑어 바꾼다. 화면이 많아지면 비용이 커지므로, 서버 렌더링으로 옮길 때는 **키 기반 번역 파일**(`ko.json` · `en.json` · `zh.json` · `ja.json`)로 바꾸고 한국어 원문을 키에서 떼어낸다
- 선택한 언어는 `localStorage` 의 `washed_lang` 에 있고 계정에 붙지 않는다(2번 표). 기기를 바꾸면 다시 골라야 하는데, 이대로 둘지는 팀이 정한다
- **서버가 만드는 문장**(알림 제목 · 내용 · 신고 결과 문구)은 지금 화면에서 번역된다. 서버 발송으로 옮기면 **푸시 알림은 번역되지 않으므로**, 사용자 언어를 서버가 알고 그 언어로 만들어 보내야 한다(5번과 함께 본다)
- 관리자가 직접 쓰는 공지는 번역하지 않는다(05 P25) — 다국어 공지가 필요하면 관리자 화면에 언어별 입력칸이 생겨야 한다
- 중국어 · 일본어 글꼴(Noto Sans SC · JP)을 구글 폰트에서 받아 쓴다. 기숙사 망에서 외부 폰트를 못 받으면 글자가 깨지므로 **자체 호스팅**을 준비해 둔다

## 12. 폰 알림(푸시) — 프로토타입에 아예 없는 것

프로토타입의 「알림」은 **알림함 목록일 뿐**이라 앱을 열어야 보인다. 폰 화면에 뜨게 하려면 아래 셋이 새로 필요하다 (R38 · P26 · F40 · F41).

| 무엇 | 어디에 | 하는 일 |
|---|---|---|
| 백그라운드 수신 코드 | `public/` 안에 파일 하나 | 앱이 닫혀 있어도 알림을 받아 폰에 띄운다 |
| 발송 키 한 쌍 | 공개 키는 화면, 비밀 키는 **서버에만**(`.env.local`) | 이 앱이 보낸 알림임을 증명한다. 비밀 키가 클라이언트로 내려가면 안 된다 |
| 기기별 구독 저장 | 06 「푸시 구독」 | 누구의 어느 기기로 보낼지. 보내다 실패하면 지운다 |

**보내는 자리는 이미 정해져 있다.** 지금 알림함에 줄을 남기는 곳마다 폰 알림도 함께 나간다 — 배정(F5) · 종료(F9) · 경고 · 신고 결과(F31). 알림함 기록은 허용 여부와 상관없이 **늘 남긴다**(P26).

**아이폰 제약.** 사파리로 열어둔 상태에서는 폰 알림이 오지 않는다. 홈 화면에 추가해야만 받으므로 홈 첫 진입에서 안내한다(F41). 이 조건을 만족하려면 앱이 홈 화면에 추가될 수 있는 형태여야 한다.

**알림 문구는 번역 사전에 있다.** 배정 · 종료 알림 두 문장(「10분 안에 QR 코드를 찍어주세요…」 · 「3분 안에 세탁물을 수거해주세요」)이 `i18n.js` 에 네 언어로 들어 있다. 다만 그 번역은 **화면이 그릴 때만** 걸리므로, 서버가 보내는 푸시는 여전히 한국어로 나간다 — 사용자 언어를 서버가 알고 그 언어로 만들어 보내야 한다(11번).
