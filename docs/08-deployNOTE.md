# 배포 · 데이터베이스 전환 시 수정 지점 — Washed

> 문서: 08-deployNOTE.md

> 지금 구조: 모든 데이터가 **브라우저 localStorage** 에 있고, 남은 시간 · 만료 판정을 **각 브라우저가 따로 계산**한다.
> 목표 구조: 데이터는 서버 DB 에, 판정은 서버가, 화면은 결과만 받아 그린다.
> 이 문서는 "어디를 고쳐야 하는가" 만 적는다. 정책 값은 05-policy.md 를 따른다.

---

## 1. 사용자 식별 · 인증 — 가장 먼저

| 위치 | 지금 | 바꿀 것 |
|---|---|---|
| `홈.dc.html` · `기록.dc.html` 상단 `MY_USER_KEY = '원병찬·302호'` | 상수 | 로그인 세션에서 받은 **사용자 ID** |
| `설정.dc.html` `submitReport` 의 `reporter: '병찬 · 302호'` | 문자열 고정 | 세션 사용자 |
| `관리자.dc.html` `userKey(u) = name·room` | 이름 + 호실 조합 | DB 의 `user_id` (동명이인 · 호실 이동 때 어긋난다) |
| `로그인.dc.html` | 검증 자체가 없다 (누구나 홈으로) | 서버 인증 → 세션 · 토큰 발급 |
| `관리자로그인.dc.html` `static ADMIN_ID` · `ADMIN_PW` | **비밀번호가 클라이언트 코드에 그대로 있다** | 서버 인증으로 옮기고 코드에서 삭제 |
| `회원가입.dc.html` 인증코드 · `비밀번호찾기.dc.html` `static CODE = '135790'` | 고정 코드 | 서버가 생성 · 메일 발송 · 검증 (코드는 절대 클라이언트로 내려보내지 않는다) |

**권한 확인이 없다.** 지금은 주소창에 `관리자.dc.html` 을 치면 누구나 들어간다. 모든 관리자 API 와 화면 진입에 역할 검사가 필요하다.

## 2. 저장소 — localStorage 키 → 테이블

| 키 | 쓰는 화면 | 옮길 곳 |
|---|---|---|
| `washed_typequeue` | 홈 · 관리자 | `queue` (사용자 · 기기종류 · 상태 · 배정시각) |
| `washed_machines` · `washed_admin_faults` | 홈 · 관리자 | `machine` (이름 · 종류 · 상태 · 고장 여부) |
| `washed_maintenance` | 홈 · 관리자 | `laundry_room.maintenance` |
| `washed_warnings` | 홈 · 기록 · 관리자 | `warning_summary` (사용자별 누적 · 제한 종료 시각) |
| `washed_warnlog` | 기록 · 관리자 | `warning` (사용자 · 사유 · 부여자 · 시각) |
| `washed_reports` | 설정 · 관리자 · 알림 | `report` (신고자 · 사유 · 기기 · 사진 · 상태) |
| `washed_notices` | 관리자 · 알림 | `notice` |
| `washed_unread` | 알림 · 홈 · 기록 · 설정 | `notification` 테이블의 읽음 여부로 계산 |
| `washed_admin_id` | 관리자로그인 | 그대로 두어도 된다 (아이디 저장 편의 기능) |

`localStorage` 는 사용자가 콘솔에서 고칠 수 있다. **경고 횟수를 0 으로 바꾸는 것도 가능하다.** 제재와 관련된 값은 반드시 서버에만 둔다.

## 3. 대기열 · 배정 — 동시성

지금은 각 브라우저의 `_reconcile()` 이 "내가 보기에 다음 차례" 를 스스로 판단한다. 사용자가 둘 이상이면 **같은 기기에 두 명이 배정될 수 있다.**

- 줄서기 · 배정 · 취소 · 종료를 **서버 API 로 옮기고**, 대기열 갱신은 트랜잭션(또는 행 잠금)으로 처리한다
- 배정은 서버가 정하고 클라이언트는 결과만 받는다 (`홈.dc.html` `_reconcile` · `queueType` · `leave` · `finish` 가 그 자리)
- "가장 먼저 끝나는 기기에 배정" (05 P2) 규칙도 서버로 옮긴다

---

## 4. 시간 · 만료 처리

| 지금 | 바꿀 것 |
|---|---|
| 브라우저의 `Date.now()` 로 남은 시간 계산 | 서버 시각 기준. 화면은 서버가 준 종료 시각까지의 차이만 그린다 |
| 화면이 켜져 있어야 만료가 처리된다 | **서버 스케줄러**가 처리한다 — 배정 10분 만료, 수거 3분 초과, 제한 3일 종료, 매월 1일 경고 초기화 |
| `setInterval(..., 1000)` 으로 화면 전체 갱신 | 서버 푸시(SSE · WebSocket)나 짧은 폴링으로 바꾼다 |

**앱을 안 켠 사람도 경고를 받아야 한다.** 지금은 화면을 열지 않으면 배정 만료 경고가 기록되지 않는다.

---

## 5. 알림

- 지금은 화면 안 토스트와 알림함 목록뿐이다. **실제 푸시가 없다**
- 배정 · 종료 · 경고 · 공지 · 신고 결과 발송을 서버에서 처리하고, 기기 토큰(FCM · APNs)을 사용자별로 저장한다
- `설정.dc.html` 의 알림 토글(`tenMin` · `ready`)은 화면 state 라 새로 고치면 초기화된다 → 사용자 설정 테이블로
- 알림 보관 30일(05 P14)은 서버 배치로 삭제한다. 지금은 `offset < 30` 으로 화면에서 거르기만 한다

---

## 6. QR 인증

- 현재 스캐너는 **카메라를 쓰지 않는 연출 화면**이다 (`홈.dc.html` `scanningId` · `closeScanner`)
- 카메라 권한 요청 + QR 디코딩 라이브러리 연결이 필요하다
- QR 값에는 기기 ID 와 함께 **위조 · 재사용을 막을 값**(서명 또는 한 번 쓰고 버리는 토큰)을 넣는다. 사진으로 찍어 두고 방에서 인증하는 것을 막아야 한다
- 서버는 "배정된 사람인가 · 그 기기가 맞는가" 를 확인한 뒤 타이머를 시작한다

---

## 7. 파일 업로드 (신고 증거 사진)

- `설정.dc.html` 의 `<image-slot>` 은 **첨부 UI 만 있고 신고 데이터에 사진이 들어가지 않는다**
- 업로드 API · 저장소(S3 등) · 용량 제한 · 보관 기간이 필요하다. 사진에는 다른 사람의 세탁물이 찍히므로 보관 기간을 짧게 두고 신고 종결 시 삭제한다

---

## 8. 화면에 박혀 있는 가짜 데이터

| 화면 | 항목 |
|---|---|
| 홈 · 관리자 | 기기 목록(세탁기 8 · 건조기 4) |
| 관리자 | 사용자 목록 `userDefs`, 신고 샘플, 공지 기본값, 이용 내역 샘플 |
| 기록 | 이용 내역 `groups` 샘플, 경고 샘플 |
| 알림 | 샘플 알림 `n1` ~ `n9` |
| 관리자 대시보드 | 혼잡도 · 예상 대기 계산에 쓰는 값 |

전부 API 조회로 바꾼다. 화면 구조는 그대로 두고 `renderVals()` 안의 배열만 교체하면 된다.

## 9. 보관 · 삭제 (05 P14 · P17 · P21 · SP4 · SP5)

- 이용 내역 · 경고 · 신고(증거 사진 포함) 3개월, 사생 기록 화면 30일, 알림 30일 → **서버 배치 삭제**
- 탈퇴는 **즉시 삭제가 아니라 14일 유예**다(05 P24) — 탈퇴 신청 시각을 저장하고, 매일 배치로 `탈퇴 신청 + 14일` 이 지난 계정의 개인정보 · 이용 내역 · 경고 · 신고 · 알림 · 업로드한 사진을 삭제한다. 익명화가 아니라 삭제다
- 복구 기간에는 로그인 시 홈 대신 복구 안내를 띄우고, 같은 학교 이메일의 신규 가입을 막는다
- 지금은 어느 것도 실제로 지워지지 않는다. 화면에서 거를 뿐이다

---

## 10. 확장할 때 걸리는 것

- **세탁실이 한 곳이라는 전제**로 되어 있다. 동 · 층이 여러 개면 기기 · 대기열 · 공지 · 점검 모드가 모두 세탁실 단위로 나뉘어야 한다
- 관리자 계정이 하나다. 동별 담당자를 나누려면 관리자에게도 소속이 필요하다
- 네트워크 오류 · 서버 점검 중의 화면이 없다. 모든 조회에 실패 상태 표시가 필요하다

## 순서 제안

1. 인증 · 세션 (1번) — 이게 없으면 나머지가 전부 "누구의 데이터인지" 를 모른다
2. 저장소 이관 (2번)
3. 대기열 · 배정 서버화 (3번) + 만료 스케줄러 (4번)
4. 실시간 갱신 · 푸시 알림 (4 · 5번)
5. QR · 사진 업로드 (6 · 7번)
6. 보관 배치 · 다중 세탁실 (9 · 10번)
